# 预测回显

预测回显只在已识别的可编辑输入区内生效。提示符和输入框形状提供编辑边界及模式提示，不按操作系统限制。菜单、输出正文、只读页面和未知区域均不启用预测，即使这些区域的输出恰好与按键内容一致。

## 工作方式

1. **定位输入区。** 当前光标必须位于可识别的提示符或输入框内。只有支持隐藏光标的已识别输入框才允许隐藏光标。未知区域没有候选预测回退路径。
2. **学习。** 最初的预测不可见，实际回显确认输入区的行为后才显示。回显建立的信任不能赋予输入区之外的位置预测权限。
3. **绘制。** 后续输入在独立覆盖层显示，使用实际回显的样式。Canvas 和 DOM 渲染使用相同预测。预测内容不写入 xterm 的真实缓冲区，也不改变发送给主机的字节。
4. **校正。** 在同步输出帧结束后核对预测。匹配时移除覆盖层；不匹配时撤销当前预测并取消信任。离开可编辑输入区后清除待确认预测及该区域的信任，包括没有待确认输入、或控制键冻结了当前预测的情况。返回输入区时需要重新验证回显。重连和调整大小会重置学习状态。
5. **过期。** 即使用户和服务器都停止活动，定时器也会清除没有得到回应的预测。截止时间随实际回显延迟调整，范围为 1.5–4 秒。

“自动”在实际回显延迟超过 40 毫秒后显示已学习的预测。“始终开启”取消延迟门槛，但仍要求识别出输入区并验证回显。“关闭”隐藏覆盖层。

## 本地延迟测试 WebUI

要使用你系统中的**真实终端和智能体**，运行 `npm run build`，再运行 `RELAY_DEV_LATENCY_MS=200 node scripts/real-terminal-preview.mjs`。它读取本机配置，连接已经运行的 Herdr 服务，预览使用独立凭据和状态目录。打开 `http://127.0.0.1:8899/__test__` 进行配对和延迟调整。Ctrl+C 停止预览连接器与中继，原有 Herdr 服务继续运行。

运行 `npm run build`，然后运行 `RELAY_DEV_LATENCY_MS=400 node scripts/e2e-latency-harness.mjs`。打开输出中的 **Test WebUI** 地址，通常为 `http://127.0.0.1:8899/__test__`。顶部面板提供预设档位和 0–5000 毫秒的自定义额外往返延迟，两个方向各增加一半。切换前等待已有帧发送完成，避免降到零延迟时输入乱序；切换期间终端连接保持不变。

测试使用模拟 shell。先输入一个字符并等待回显，再连续输入和退格。可在 WebUI 设置中对比预测模式；“自动”的平滑延迟估计需要几次回显更新。延迟面板及其 HTTP 路由只由测试脚本安装。

## 边界与验证

陌生 TUI 的输入区必须先能被识别为可编辑区域，才能启用预测。仅有相同字符回显或光标移动不够。不能确认的区域默认关闭，优先保证不在非输入区域显示预测。

退格只在已知可编辑文字范围内预测。边缘换行、任意光标导航、宽度不确定的 emoji 和应用特有编辑行为等待实际输出。终端画面无法揭示所有程序的内部状态；输入区识别提供必要的范围限制，实际回显验证范围内的输入行为。

回归测试覆盖已识别输入框、shell 提示符、模拟 CMD 和 PowerShell 提示符、窄屏及中文双宽字符。负向测试在空白区域、输出正文、未知提示符、Herdr 帮助、less、Vim 普通模式及智能体菜单中制造与输入一致的输出，确认均不会启用预测。另覆盖离开并返回输入区、过期清理、密码掩码和 DOM 回退。真实 xterm 解析器测试覆盖增量 ANSI 输出、备用屏幕和跨多次写入的同步重绘，不代表已在每一种智能体或真实 Windows 主机上完成验证。

此前已用本地 Chromium 检查 DOM 覆盖层的位置、双宽字符尺寸、学习得到的颜色，以及真实缓冲区未被修改。不匹配诊断省略原始字符，避免掩码输入出现在调试面板。

回显验证与真实缓冲区之外的覆盖层设计参考通过 Exa 找到的 [Mosh 论文](https://mosh.org/mosh-paper.pdf)及其[预测实现](https://github.com/mobile-shell/mosh/blob/master/src/frontend/terminaloverlay.cc)。本实现额外要求识别出可编辑输入区，不从任意输出中学习输入位置；仅收到传输层回执也不能证明应用已经绘制了输入。
