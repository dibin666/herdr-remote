# 预测回显

预测回显根据终端的实际行为学习，不要求智能体或操作系统在支持名单中。未知 TUI 输入区、编辑器、自定义 shell 提示符和 Windows 终端都可以在学习后提前显示输入。已识别的提示符和输入框继续提供编辑边界和模式提示。

## 工作方式

1. **观察。** 在未知界面的光标位置建立候选区域，以窗格边缘为界。允许隐藏终端光标，因为很多 TUI 会自己绘制光标。
2. **学习。** 最初的预测不可见。至少两个字符所在单元格确实发生改变、内容匹配实际输出，并且光标在同一行越过这些字符后，才建立信任。已有文字、空白删除和后台重绘不能建立信任。已识别输入区保留原有的一次回显预热方式。
3. **绘制。** 后续输入在独立覆盖层显示，使用实际回显的样式。Canvas 和 DOM 渲染使用相同的预测。预测内容不写入 xterm 的真实缓冲区，也不改变发送给主机的字节。
4. **校正。** 在同步输出帧结束后，用解析完成的输出核对预测。匹配时移除覆盖层；不匹配时撤销当前预测并取消信任。未知区域遇到控制键、指针操作、提示符上下文变化、光标可见性变化或移到其他行时重新学习。重连和调整大小会重置学习状态。
5. **过期。** 即使用户和服务器都停止活动，定时器也会清除没有得到回应的预测。截止时间随实际回显延迟调整，范围为 1.5–4 秒。未知区域过期后需要重新建立信任。

“自动”在实际回显延迟超过 40 毫秒后显示已学习的预测。“始终开启”取消延迟门槛，但仍需验证回显。“关闭”隐藏覆盖层。调试面板用 `observed` 标识未识别的候选区域。

## 边界与验证

一致的效果指各平台遵循同一套学习和校正规则，不能保证任意操作都立即得到准确预测。只看终端画面，客户端无法知道下一个按键会插入文字、执行命令、切换模式还是输入密码。不变或掩码回显不会训练未知区域的预测器。程序也可能在没有可见信号时改变行为；错误猜测会在收到反馈或超时后撤销。

退格只在已知可编辑文字范围内预测；未知区域保护初始光标之前的所有内容。边缘换行、任意光标导航、宽度不确定的 emoji 和应用特有编辑行为等待实际输出，避免把某个程序的编辑规则套用到其他程序。

回归测试覆盖自定义及隐藏光标的 TUI、无边框编辑区、模拟 CMD 和自定义 PowerShell 提示符、窄屏、中文双宽字符、密码掩码、与菜单已有文字偶合、模式切换、过期清理和 DOM 回退。真实 xterm 解析器测试覆盖增量 ANSI 输出、备用屏幕和跨多次写入的同步重绘。这些是可重复的终端输出测试，不代表已在每一种智能体或真实 Windows 主机上完成验证。

另通过本地 Chromium 检查 DOM 覆盖层的位置、双宽字符尺寸、学习得到的颜色，以及真实缓冲区未被修改。不匹配诊断省略原始字符，避免掩码输入出现在调试面板。

设计参考通过 Exa 找到的 [Mosh 论文](https://mosh.org/mosh-paper.pdf)及其[预测实现](https://github.com/mobile-shell/mosh/blob/master/src/frontend/terminaloverlay.cc)：先进行不可见的试探，再以真实屏幕校正覆盖层。本项目的流协议没有 Mosh 那样的应用回显确认；仅收到传输层回执，不能证明应用已经绘制了输入。
